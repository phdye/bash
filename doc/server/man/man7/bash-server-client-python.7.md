# BASH-SERVER-CLIENT-PYTHON(7) -- Python client binding for bash-server

# DESCRIPTION

The Python client binding provides an async/await interface to the
bash-server v2 NDJSON protocol.  It is implemented as the `bashclient`
package, requires Python 3.8 or later, and depends only on the Python
standard library (`asyncio`, `base64`, `json`, `socket`,
`subprocess`).

The binding is fully asynchronous, built on `asyncio`.  All channel
operations are coroutines that must be awaited.  A background reader
task dispatches incoming messages to per-channel queues and registered
callbacks.

# CONCEPTS

# Installation

The package is located at `bash-server/clients/python/` and uses `pyproject.toml`
with setuptools as the build backend:

```sh
cd bash-server/clients/python
pip install -e .
```

For development with test dependencies:

```sh
pip install -e ".[dev]"
```

This installs `pytest>=7` and `pytest-asyncio>=0.21`.  Tests are run
with:

```sh
pytest
```

The `pyproject.toml` sets `asyncio_mode = "auto"` for pytest-asyncio,
so test functions can use `async def` directly without decorators.

# Package structure

```
bashclient/
    __init__.py      -- Package exports
    client.py        -- BashClient class
    channels.py      -- Six channel classes
    errors.py        -- Exception hierarchy
    protocol.py      -- NDJSON encode/decode, base64 helpers
    transport.py     -- Four transport implementations
    types.py         -- Dataclass definitions
```

# Architecture

The central class is `BashClient`.  It owns a `Transport` instance and
runs a background `asyncio.Task` (the reader loop) that continuously
reads NDJSON lines from the transport.

Incoming messages are routed by channel ID:

- **Request/response messages** are placed on per-channel
  `asyncio.Queue` instances.  When a channel method sends a request,
  it awaits the corresponding queue for the response.

- **Server-push messages** (observe events, debug break_hit, PTY
  output/exit) are dispatched directly to registered callbacks via the
  channel's `dispatch()` method.

Each channel is exposed as a public attribute on the client:

```python
client.control   # ControlChannel  (CHAN_CONTROL = 0)
client.command   # CommandChannel  (CHAN_COMMAND = 1)
client.state     # StateChannel    (CHAN_STATE = 2)
client.observe   # ObserveChannel  (CHAN_OBSERVE = 3)
client.debug     # DebugChannel    (CHAN_DEBUG = 4)
client.pty       # PtyChannel      (CHAN_PTY = 5)
```

# Connection

`BashClient` provides four class methods for establishing connections,
each returning a `BashClient` instance with the reader task already
running:

```python
# Unix domain socket (default)
client = await BashClient.connect("/tmp/bash-server-1000/sock")

# Subprocess (--stdio mode)
client = await BashClient.connect_stdio("bash-server", "--stdio")

# Inherited file descriptor
client = await BashClient.connect_fd(3)

# Windows Named Pipe (Cygwin)
client = await BashClient.connect_named_pipe("\\\\.\\pipe\\bash-server-myname")

# From existing transport
client = await BashClient.from_transport(my_transport)
```

All factory methods are `async` and must be awaited.  They instantiate
the appropriate `Transport` subclass, call its `connect()` method, and
start the background reader.

# Async context manager

`BashClient` supports `async with` for automatic cleanup:

```python
async with BashClient.connect(socket_path) as client:
    await client.auth(token)
    result = await client.eval("echo hello")
    print(result.stdout)
# close() called automatically on exit
```

The `__aexit__` method sends a `disconnect` message, cancels the reader
task, and closes the transport.  This is the recommended usage pattern.

Manual lifecycle is also supported:

```python
client = await BashClient.connect(socket_path)
try:
    await client.auth(token)
    # ... use client ...
finally:
    await client.close()
```

# Authentication

After connecting, the client must authenticate before using any channel
except CHAN_CONTROL:

```python
await client.auth(token)
```

The token is a 64-character hex string (256-bit) generated by the
server at startup.  If authentication fails, `AuthError` is raised.

The `is_authenticated` property indicates whether `auth()` has
completed successfully:

```python
if client.is_authenticated:
    result = await client.eval("whoami")
```

# Type system

All protocol objects are defined as `dataclasses` in `bashclient.types`:

| Dataclass          | Fields                                          |
|--------------------|-------------------------------------------------|
| `EvalResult`       | `stdout`, `stderr`, `exit_code`                 |
| `VarInfo`          | `name`, `value`, `attributes`                   |
| `FuncInfo`         | `name`, `definition`                            |
| `AliasInfo`        | `name`, `value`                                 |
| `TrapInfo`         | `signal`, `command`                             |
| `PreCommandEvent`  | `seq`, `timestamp`, `command`, `cwd`, `line_number`, `is_subshell`, `is_async` |
| `PostCommandEvent` | `seq`, `timestamp`, `command`, `exit_status`, `signal_number`, `duration_ms` |
| `Breakpoint`       | `id`, `kind`, `enabled`, `hit_count`, `pattern`, `line`, `condition` |
| `BreakHitEvent`    | `line`, `command`, `depth`                      |
| `DebugStatus`      | `active`, `mode`, `breakpoints`, `depth`        |
| `PtyInfo`          | `rows`, `cols`, `pid`, `strip_ansi`             |

Channel methods return these dataclasses directly rather than raw
dictionaries, providing type safety and IDE autocompletion.

# Error handling

All errors inherit from `BashClientError`:

```
BashClientError
    AuthError          -- Authentication failed
    ProtocolError      -- Malformed frame or message
    TimeoutError       -- Operation timed out
    TransportError     -- Socket or I/O error
    ServerError        -- Server returned error response
        .channel       -- Channel that produced the error
```

Standard `try`/`except` patterns apply:

```python
from bashclient.errors import AuthError, TimeoutError, ServerError

try:
    await client.auth(wrong_token)
except AuthError:
    print("bad token")

try:
    result = await client.eval("sleep 60", timeout=5.0)
except TimeoutError:
    print("command timed out")

try:
    info = await client.state.get_var("NONEXISTENT")
except ServerError as e:
    print(f"server error on channel {e.channel}: {e}")
```

# CONTROL channel (channel 0)

Session lifecycle operations:

```python
# Authenticate
await client.auth(token)

# Ping/pong keepalive
await client.ping()

# Configure session (e.g., enable observe)
await client.control.configure(observe_level=1)

# Graceful disconnect
await client.control.disconnect()
```

# COMMAND channel (channel 1)

Command evaluation with stdout/stderr capture:

```python
# Simple eval (convenience method on client)
result = await client.eval("echo hello")
print(result.stdout)   # "hello\n"
print(result.stderr)   # ""
print(result.exit_code) # 0

# With custom timeout
result = await client.eval("sleep 2 && echo done", timeout=10.0)

# Via channel object directly
result = await client.command.eval("ls -la", id="req-001")
```

The `eval()` method collects three response messages (`stdout`,
`stderr`, `complete`) and returns an `EvalResult` dataclass.
stdout and stderr payloads are automatically base64-decoded.

# STATE channel (channel 2)

Direct manipulation of shell state across four namespaces:

```python
# Variables
info = await client.state.get_var("HOME")
print(info.value)        # "/home/user"
print(info.attributes)   # []

await client.state.set_var("MY_VAR", "hello", attributes=["-x"])
await client.state.unset_var("MY_VAR")

# Functions
func = await client.state.get_func("my_function")
print(func.definition)

await client.state.unset_func("my_function")

# Aliases
alias = await client.state.get_alias("ll")
print(alias.value)       # "ls -la"

await client.state.set_alias("ll", "ls -la --color")
await client.state.unset_alias("ll")

# Traps
await client.state.set_trap("SIGINT", "echo interrupted")
await client.state.unset_trap("SIGINT")

# Inspect (list all items of a type)
items = await client.state.inspect("variables")
for item in items:
    print(f"{item['name']}={item.get('value', '')}")
```

# OBSERVE channel (channel 3)

Subscribe to pre/post command events with callbacks:

```python
# Subscribe at level 1
await client.observe.subscribe(level=1)

# Register callbacks (sync or async)
def on_pre(event: PreCommandEvent):
    print(f"[{event.seq}] running: {event.command} in {event.cwd}")

async def on_post(event: PostCommandEvent):
    print(f"[{event.seq}] done: {event.command} exit={event.exit_status} "
          f"duration={event.duration_ms}ms")

client.observe.on("pre_command", on_pre)
client.observe.on("post_command", on_post)

# Execute commands -- callbacks fire automatically
await client.eval("echo hello")
await client.eval("ls /nonexistent")

# Unregister a specific callback
client.observe.off("pre_command", on_pre)

# Unregister all callbacks for an event type
client.observe.off("post_command")

# Unsubscribe
await client.observe.unsubscribe()
```

Both synchronous and async callbacks are supported.  The dispatch
method detects coroutine functions and awaits them automatically.

# DEBUG channel (channel 4)

Interactive debugging with breakpoints, stepping, and AST inspection:

```python
# Enable debugger
await client.debug.enable()

# Check status
status = await client.debug.status()
print(f"active={status.active} mode={status.mode}")

# Add breakpoints
bp_id = await client.debug.add_breakpoint("command", pattern="echo*")
bp_id2 = await client.debug.add_breakpoint("line", line=10)
bp_id3 = await client.debug.add_breakpoint("function", pattern="my_func")

# List breakpoints
bps = await client.debug.list_breakpoints()
for bp in bps:
    print(f"#{bp.id} {bp.kind} hits={bp.hit_count} enabled={bp.enabled}")

# Register break_hit callback
async def on_break(event: BreakHitEvent):
    print(f"break at line {event.line}: {event.command}")
    ast = await client.debug.inspect_ast()
    print(f"AST: {ast}")
    await client.debug.step()

client.debug.on("break_hit", on_break)

# Execution control
await client.debug.continue_()   # note trailing underscore
await client.debug.step()
await client.debug.next()
await client.debug.finish()
await client.debug.skip()

# Inspect AST at current break point
ast = await client.debug.inspect_ast()

# Remove breakpoint
await client.debug.remove_breakpoint(bp_id)

# Enable/disable without removing
await client.debug.disable_breakpoint(bp_id2)
await client.debug.enable_breakpoint(bp_id2)

# Disable debugger
await client.debug.disable()
```

Note that `continue_()` has a trailing underscore to avoid conflicting
with the Python `continue` keyword.

# PTY channel (channel 5)

Pseudo-terminal spawning and interactive I/O:

```python
# Spawn a PTY
info = await client.pty.spawn(rows=24, cols=80, strip_ansi=True)
print(f"PTY pid={info.pid} {info.rows}x{info.cols}")

# Register output callback
def on_output(data: str):
    print(data, end="")

def on_exit(exit_code: int):
    print(f"\nPTY exited with code {exit_code}")

client.pty.on("output", on_output)
client.pty.on("exit", on_exit)

# Send input (automatically base64-encoded)
await client.pty.write_input("ls -la\n")

# Resize terminal
await client.pty.resize(rows=48, cols=120)

# Send signal
await client.pty.signal("SIGINT")

# Close PTY
await client.pty.close()
```

PTY output is automatically base64-decoded.  When `strip_ansi=True` is
set during spawn, ANSI escape sequences are removed server-side before
transmission.

# Callback model

The observe, debug, and PTY channels use an `on`/`off` callback
registration pattern:

```python
# Register
channel.on("event_name", callback)

# Unregister specific callback
channel.off("event_name", callback)

# Unregister all callbacks for an event
channel.off("event_name")
```

Callbacks can be either synchronous functions or async coroutines.
The dispatch system detects coroutine functions with
`asyncio.iscoroutinefunction()` and awaits them when appropriate.

Multiple callbacks can be registered for the same event.  They are
invoked in registration order.

# Complete example

```python
import asyncio
from bashclient import BashClient

async def main():
    async with BashClient.connect("/tmp/bash-server-1000/sock") as client:
        # Authenticate
        await client.auth("abcdef0123456789...")

        # Simple command
        result = await client.eval("echo hello world")
        assert result.exit_code == 0
        print(result.stdout)

        # Set and read a variable
        await client.state.set_var("GREETING", "hello")
        info = await client.state.get_var("GREETING")
        assert info.value == "hello"

        # Subscribe to observations
        events = []
        client.observe.on("post_command", lambda e: events.append(e))
        await client.observe.subscribe()
        await client.eval("true")
        await asyncio.sleep(0.1)
        print(f"Captured {len(events)} events")

asyncio.run(main())
```
